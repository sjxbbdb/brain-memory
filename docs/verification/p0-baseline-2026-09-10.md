## 固定评估契约

- `HARNESS_SCHEMA_VERSION=1`，`HARNESS_VERSION="0.1.0"`。
- 默认候选资源上限：10 秒、2,048 个文件、单文件 8 MiB、总计 64 MiB、stdout/stderr
  各 64 KiB、合计输出 128 KiB。
- `BaselineRevision` 必须与当前 harness version、fixture hash 和 evaluator hash 一致；
  `EVOLUTION` 还须在主维度严格改善且关键维度无重大回归，`RECOVERY` 只允许恢复可信
  基线。随机测试使用显式固定 seed，不允许候选改变夹具、seed、资源预算或裁判。
- 生产 `PromotionController` 必须使用活动树之外的 file-backed ledger、外置 transaction
  manifest、绝对 persistence path 和一次性 `SandboxAttestation`；测试/离线兼容必须
  显式使用 `profile="legacy"`。

## 资源与身份基线

默认每 100 tick 的 Homeostasis 预算为：compute 300,000 ms、memory 512 MiB、storage
4,096 MiB、network 100 次、model 50,000 tokens、action risk 10、attention load 1；
warning/critical 比例为 0.7/0.9。部署宿主可以收紧这些上限，不能借修改测试预算制造进步。

新 `LifeKernel` 的可复现结构为：schema 1、generation 0、parent 为 null、状态 `CREATED`、
genesis sequence 1、append-only ledger 校验通过；lineage/instance ID 每次由宿主生成，不能
把本文的样例或产品版本号当作真实身份。SQLite lease/fencing、life ledger、anchor vault、
succession ledger 和 motivation replay ledger 都必须位于候选可交换树之外。
